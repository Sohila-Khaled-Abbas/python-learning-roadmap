# Build 02 · PixelFed quality CLI

Profile landing data and publish a quality report without rewriting source files.

Extension beyond the Boot.dev video

## Connect to your work

Extend your PixelFed contracts; social posts and profiles are not sales transactions.

## Learn by doing

- Inspect actual PixelFed filenames and grain before choosing checks.
- Report missing IDs, invalid timestamps, duplicates and orphans.
- Write a small JSON report and a quarantine file.

## Original practice

Follow projects/02-pixelfed-quality.md using a copied sample, never the only landing copy.

## Exit check

Every rule has a test and an example; no indiscriminate fillna(0).

## Understand the idea

A quality rule needs a business meaning, severity and action. Profile a copied sample, then separate unacceptable identifiers from optional attributes whose unknown value may be valid.

Report the denominator for every percentage and preserve rejected records with reasons. Compare before/after quality using stable definitions; a smaller output is not automatically a cleaner one.
